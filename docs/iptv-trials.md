# IPTV 自动试用

在“自动回复设置 → IPTV 自动试用”保存供应商密钥、频道范围和每日上限，确认供应商后台 Demo 已设为 12 小时，再为当前 WhatsApp 会话启用。供应商密钥、播放服务器、时长确认和每日额度共享；会话开关及频道范围独立。

供应商成功创建试用但返回的播放链接缺少域名时，可配置“播放服务器地址”，例如 `https://playback.example:8443`。填写公开 HTTP(S) 服务器地址，可带端口，不要包含账号密码、路径、查询参数或片段；留空关闭补全。系统仅在明确成功、账号密码完整且唯一、链接为缺域名的 `/get.php` 格式时使用该地址；正常完整链接保持原样。内网、本机地址及数字形式的本机地址别名不能作为播放服务器。保存地址后，“检查供应商接口”仍只验证供应商账号与套餐，不验证频道播放。

本集成固定使用 Activation Panel 官方文档的 HTTPS API 地址，创建 M3U 试用时发送 `sub=99`。默认 `pack=all`，每日全局最多自动开通20个，可调整为1–1000。12小时为供应商后台设置，软件不会通过本地计时修改或延长供应商账号。显示的预计到期时间以本地成功申请时刻加12小时计算；供应商接口当前仅返回到期日期。

客户明确要求测试 IPTV 时，AI 发出结构化申请，后台再次检查客户意图、会话连接、自动回复时段、人工接管、当前配置和额度后开通。在最近聊天上下文已经明确是 IPTV 对话时，客户单独发送“测试、试用、体验、test、trial”等短词也按测试请求处理；没有 IPTV 上下文的普通短词仍不会开通。询价、介绍和播放故障不会直接开通。每个聊天窗口（当前 WhatsApp 技术会话 + 当前聊天身份）仅有一次试用机会；同一窗口在账号有效期间重复请求只能取回原账号，过期后拒绝再次开通。不同聊天窗口分别计算资格，跨会话可以各自生成一次。领取记录保留在共享数据库中，服务重启、关闭再启用功能或更换供应商密钥都不会重置同一聊天窗口的资格；界面没有重置资格入口。

自动测试请求支持中文、英语、葡萄牙语、西班牙语、法语、阿拉伯语、土耳其语、德语、俄语、意大利语及常见的日语、韩语、荷兰语、越南语和印尼语表达。AI 没有返回受控开卡工具时，后台会对明确请求做同样的意图复核和兜底开通；对上一条系统自动 IPTV 测试邀请的肯定短答也可继续申请，管理员手动发送的卡密不会被当作邀请。回复语言按当前消息、最近上下文、英语回退。

供应商拒绝、超时、返回无法核实或发送失败的自动测试会进入持久化重试队列，使用逐步增加且有上限的间隔，服务重启后继续，直到成功发送、自动 IPTV 被关闭或会话被删除。旧版本留下的 `unknown/creating` 记录如果没有重试任务，下一次明确测试请求会为原记录补建一次创建重试，不会新增第二条自动资格记录。发送阶段已有账号时只重发该账号，不重新申请。供应商未知结果可能在外部已经创建账号；供应商接口没有幂等键，系统会保证同一记录不会并发重试，但无法消除上游重复账号风险。WAHA 外部发送与本地状态写入无法组成一个原子事务，若进程恰在外部发送成功后中断，恢复时可能再次发送同一已创建账号，但不会重新申请供应商账号。

聊天窗口的输入框附近提供“生成并发送”手动卡密入口，可选择“测试、1个月、3个月、6个月、12个月”。手动开卡不检查客户是否已经领取过自动测试，也不消耗自动测试资格；同一会话、同一客户聊天窗口内的请求 ID 只会创建一次，新的点击可再次创建，其他聊天窗口不能重放该请求 ID 来复用卡密。手动供应商创建失败不会自动重建，管理员使用新的请求再次点击；手动账号已经创建但发送失败时只重发该已创建账号。浏览器和普通日志不会显示卡密，客户会直接收到实际账号信息。

手机号格式的 c.us、s.whatsapp.net 和 LID 都可以作为当前聊天窗口身份参与一次开通。系统不再要求先把 LID 映射为手机号；LID 在同一聊天窗口重复请求时复用该窗口已有账号，换到另一个聊天窗口则按新窗口资格处理。客户身份仍使用脱敏 HMAC 保存，不会在记录、标签或普通日志中写入手机号或 LID。

安装脚本会在成功后同时提示面板和 WAHA 的账号，并只显示密码/API Key 的掩码值；真实值只保存在 `.env` 和 `secrets/` 目录的受限文件中。

API 密钥和试用登录信息使用现有面板数据密钥加密。管理员读取配置只能看到“已配置”状态；开通记录不返回账号或密码。自动发送凭据仍会出现在对应客户的 WhatsApp 对话中，但面板归档的 AI 上下文及动态记忆输入会隐藏本次试用凭据。总结、建议回复、优化翻译、自动跟进、单条 AI 翻译和阿里云机器翻译也在最终请求边界统一过滤已知试用凭据。

创建请求超时、连接异常、无效返回或进程中断后的自动记录会持续进入重试队列，不要求人工核对；若供应商已经创建但响应未知，重复开卡风险仍受供应商接口无幂等键限制。自动发送失败时保留当前聊天窗口已创建的账号，只重发该账号。关闭自动开通、人工接管或连接周期变化会暂停未发送记录的自动重试；已创建账号仍保存。若在供应商调用前取消而没有实际开通，当前窗口下一条新的申请可重新预留资格。供应商已经创建的账号不能通过本地回滚撤销。手动开卡创建失败仍保持终态，管理员需使用新的请求再次点击。
手动卡密发送确认成功后会幂等写入只读系统标签“IPTV测试过”，并创建一个 12 小时后的测试体验跟进任务。跟进任务的中文源文案在数据库中加密保存，真正发送时再按客户最近的入站语言翻译；卡密创建失败、发送失败或状态未知时不会提前写入标签或跟进任务。

试用消息只有在供应商创建或复用成功、WhatsApp 消息发送成功并完成发送状态记录后，才会给当前聊天窗口添加只读系统标签“IPTV测试过”。创建失败、结果未知、发送失败和发送前取消都不会添加标签；不同聊天窗口分别保存自己的系统标签。该标签存放在独立的系统标签表中，标签窗口只展示“系统”分组，不开放编辑或删除。标签写入失败不会回滚已经成功发送的消息，只记录不含凭据的告警并等待后续成功事件幂等补写。

“检查供应商接口”只读取已保存账号状态和套餐列表，不创建账号。不自定义套餐时，供应商可能返回 `Empty custom bouquet`，不影响使用 `all`。

本次手机端修复让聊天详情继承外层工作区剩余高度，并在支持的浏览器中跟随可视视口变化。浏览器自动化已覆盖手机宽度、横屏、缩小视口、多行输入和夜间主题；真实手机软键盘及安全区仍需在实际设备上验证。
