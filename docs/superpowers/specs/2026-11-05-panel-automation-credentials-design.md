# 面板自动化、凭据展示与错误诊断设计

## 意图

在当前已部署的 waha-panel 1.0.20 代码基础上，修复自动回复和客户动态记忆的 AI 上游错误可诊断性，完善人工接管恢复设置，补齐手动 IPTV 测试卡密的标签、客户语言和体验跟进，并扩展跟进任务的短时延选项。安装脚本同时提供可操作但不泄露真实密钥的凭据提示。

## 目标

- 安装完成后明确区分面板账号和 WAHA 账号，真实密码、API Key 不写入网页、系统日志、聊天记录或最终回复；本机安装提示只显示账号、掩码值和受限凭据文件位置。
- 人工接管/人工发送后，自动恢复 AI 的时间按会话设置选择 10 分钟、30 分钟、1 小时或 5 小时，旧数据默认 5 小时。
- 手动 IPTV 卡密交付成功后幂等写入系统标签“IPTV测试过”，重试成功路径也执行相同动作。
- 手动测试卡密交付成功后自动创建 12 小时后的客户语言体验询问；客户新消息或人工接管会沿用现有跳过规则。
- 手动卡密文案优先按最近客户入站消息识别语言，避免历史客服中文覆盖客户语言。
- 将 AI 402、配置缺失、连接失败、响应格式错误等分成安全错误码；客户记忆对不可重试的上游错误停止无意义重试并保留旧记忆。
- 跟进任务延迟支持 1 小时、2 小时、3 小时、6 小时、12 小时、24 小时、3 天、7 天和 15 天；UI 使用离散滑杆/输出值，API 仍传稳定的 delay code。

## 非目标

- 不绕过 AI 服务商的余额、订阅或权限限制；HTTP 402 的根因仍需在 AI 服务商侧充值、恢复订阅或更换可用配置。
- 不恢复 1.0.16 已移除的固定自动回复兜底文案。
- 不改变 WAHA 协议、会话认证、媒体卷、消息卷或客户聊天数据结构的既有语义。
- 不删除持久化卷、不覆盖生产 SQLite、不在本次实现中重启生产容器或发布镜像。

## 约束与安全边界

- 目标实现工作树为 `github-waha-panel.worktrees/chat-engagement`，对应当前生产面板 1.0.20 代码线。
- 所有数据库迁移必须幂等；旧的聊天、跟进、卡密、客户记忆和发送幂等记录必须保留。
- 新增的错误日志只能包含稳定错误码、HTTP 状态和脱敏引用，禁止记录 API Key、密码、完整卡密 URL、客户聊天 ID 或跟进固定文案。
- 安装脚本不在 stdout、网页或日志中输出真实密码/API Key；使用账号、掩码值和本机受限文件路径提示。
- 自动卡密体验跟进只有在发送状态确认成功后创建；重复 webhook、重复请求或重试必须幂等。

## 方案比较

### 方案 A：在现有服务边界上做增量修复（采用）

沿用 `PanelState`、`ChatService`、`IptvService`、`ChatAutomationService` 和现有 SQLite 迁移机制。新增会话设置、跟进延迟 code、错误分类和少量回调；通过一个兼容迁移扩展 `follow_up_tasks` 的 CHECK 约束，保留现有任务。优点是接口和回滚面小，现有 1.0.20 测试可以直接复用；代价是 `app.py` 和聊天页面仍是现有的集成入口，需要严格按测试切片修改。

### 方案 B：重做事件流水线和凭据页面

为卡密交付、体验跟进和 AI 健康状态建立全新的事件表、后台队列和凭据管理页面。隔离性更强，但需要新的迁移、后台生命周期和 UI 权限边界，无法降低 402 的外部计费根因，回归和发布风险明显更大。

采用方案 A，因为本次需求的每个行为已有对应服务和幂等账本，新增字段与回调即可完成，不需要扩大部署边界。

## 设计决定

1. **人工恢复时长**：在 `session_settings` 增加 `human_takeover_resume_delay`，保存 code `10m|30m|1h|5h`；`ChatService` 从设置加载秒数，默认 `5h`。接管点击和成功人工文字/图片发送都基于当前时间重新设置 `auto_resume_at`。
2. **跟进延迟**：将 `DELAY_SECONDS` 扩展为 `1h=3600`、`2h=7200`、`3h=10800`、`6h=21600`、`12h=43200`、`24h=86400`、`3d=259200`、`7d=604800`、`15d=1296000`。现有表通过新迁移重建为相同字段和索引，复制所有行后替换旧表；任务状态和幂等 UUID 不变。
3. **跟进滑杆**：前端以离散数组保存 code、中文标签和秒数，`input[type=range]` 的 value 是数组索引，`output` 显示当前标签；提交仍发送 `delay_code`，不把展示文本当作 API 值。
4. **测试卡密标签和体验跟进**：在 `PanelState` 提供一个幂等的 `record_iptv_manual_delivery_success(session, chat_id, card)` 回调。它先写系统标签，再用 `ChatAutomationService.create_task(..., delay_code='12h', mode='FIXED', fixed_copy=..., client_request_id='iptv-manual-follow-up:<card_id>')` 创建体验询问；`create_task` 接受可选的稳定 `client_request_id`，重复调用按唯一键返回已有任务，不重复发送或建任务。重试 worker 通过相同回调补齐标签和任务。
5. **客户语言**：新增 `infer_customer_language_from_history`，只读取历史中标记为客户/入站的文本，按最近消息优先；当前手动卡密请求仍优先使用请求文本，其次才使用客户历史，最后英语回退。
6. **AI 错误与记忆 worker**：定义安全的 AI 上游错误码映射，`HTTPError.code == 402` 映射为 `AI_PAYMENT_REQUIRED`。客户记忆 worker 将错误码写入 `customer_memories.last_error_code` 和任务 `last_error_code`；对 402、配置缺失等确定性错误标记为终止/暂停状态，不按指数退避反复告警；网络超时和 5xx 仍可重试。
7. **安装提示**：shell 和 PowerShell 安装脚本继续把真实凭据写入原有受限文件；首次安装成功后只输出账号、掩码后的值和文件路径，已有安装只提示文件路径和“凭据已保留”。

## 验证标准

- 新增测试先失败，再实现到通过；至少覆盖迁移保留旧任务、全部延迟 code、滑杆提交、恢复时长、手动卡密标签/跟进幂等、语言识别、402 分类和记忆 worker 终止重试。
- 现有客户记忆、聊天接管、自动回复、IPTV、跟进、路由和前端语法测试全部通过。
- `git diff --check` 通过；测试输出不包含真实凭据、客户 ID、卡密 URL 或固定文案内容。
- 本地验证完成后只读核对生产容器和镜像；未获得单独部署授权前不替换生产镜像。
