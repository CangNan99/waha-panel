# 客户记忆、当前聊天全局翻译与聊天列表滚动修复设计

日期：2026-10-01  
适用分支：`feature/chat-engagement-1.0.3`  
目标产品：WhatsAPP AI 管理面板

## 1. 目标与已确认范围

本次更新同时处理三个互相关联但可以独立回滚的能力：

1. 最近聊天列表在打开客户、轮询、读取备注/标签或接收实时事件后，保持用户当前的滚动位置。
2. 在“自动回复设置”中增加客户记忆总开关。开启后按客户加密保存对话摘要、客户偏好、有效人工回复经验和未解决事项，并在后续 AI 自动回复中注入；关闭后停止生成、更新和使用记忆，但保留已有记忆。
3. 在当前聊天框顶部增加“全局翻译”开关。每个客户独立、默认关闭；开启后只翻译当前打开聊天中已加载的消息，不处理未打开聊天。客户、AI 回复和人工回复的非中文文本使用阿里云机器翻译接口显示中文译文。

用户已经确认以下行为：

- 全局翻译开关按客户独立保存于当前页面状态，默认关闭；切换客户不继承上一个客户的开关状态，刷新页面后恢复关闭。
- 全局翻译不调用现有 AI 翻译接口。
- 记忆采用客户动态记忆，不修改模型权重。
- 记忆开关放在“自动回复设置”的“回复规则”区域。
- 全局翻译开关和人工接管/恢复 AI 控件使用动态呼吸动画，并支持减少动态效果。

附件截图只作为最近聊天列表的视觉参考，不改变功能边界。

## 2. 非目标

本次不包含以下内容：

- 不进行模型微调、权重更新或外部向量数据库建设。
- 不修改 WAHA 服务的数据模型或 WhatsApp 原始消息。
- 不为未打开的聊天建立机器翻译后台任务。
- 不把机器译文写入客户记忆，记忆只使用原始对话内容。
- 不删除现有的销售 AI 建议能力；但消息气泡上的旧“翻译为中文” AI 操作不再作为全局翻译入口。
- 不在本次变更中部署到远端、重启容器或更改生产凭据。

## 3. 当前基线与问题定位

当前聊天页由 `panel/chat_page.py` 提供。聊天列表渲染会重建列表容器内容，异步客户元数据和实时事件可能在用户滚动后再次触发该渲染，因此滚动容器失去原来的可视位置。聊天头部已有人工接管状态胶囊和“人工接管/恢复 AI 回复”按钮，顶部工具栏已有独立的 AI 翻译设置入口，消息气泡还存在单条消息 AI 翻译操作。

当前自动回复设置由 `panel/app.py` 提供，设置按 WhatsApp 技术会话保存，已有全时段开关、按时间段开关、历史上下文条数、人设和系统提示词等字段。客户消息归档和摘要相关能力已经存在，可以在其上增加来源标识、客户记忆表和记忆任务表。

当前阿里云方案采用服务端 SDK 调用机器翻译。阿里云通用翻译接口支持 `SourceLanguage=auto`、`TargetLanguage=zh` 和 `FormatType=text`；单次文本长度、QPS 和语言代码需要在服务端校验。实现使用官方 Python SDK，具体接口约束以[阿里云 Python SDK 文档](https://www.alibabacloud.com/help/en/machine-translation/developer-reference/python-sdk)、[TranslateGeneral 调用说明](https://help.aliyun.com/zh/machine-translation/developer-reference/api-reference-machine-translation-universal-version-call-guide)、[接口限制](https://help.aliyun.com/zh/machine-translation/developer-reference/limits)和[支持的语言代码](https://help.aliyun.com/zh/machine-translation/support/supported-languages-and-codes)为准。

## 4. 用户可见行为

### 4.1 最近聊天列表

用户在最近聊天列表向下滚动后打开任意客户，左侧列表保留原来的可视客户和相对位置。打开聊天后，以下异步操作不会使列表回到顶部：

- 实时消息刷新；
- 定时轮询；
- 客户备注、标签、总结和跟进信息加载；
- 记忆状态刷新；
- 当前聊天机器翻译结果返回。

用户主动搜索、切换“全部/只看未读”筛选或重新加载新结果时，列表可以回到新结果的起始位置。列表为空或原锚点被筛选掉时，使用安全的 `scrollTop` 兜底。

### 4.2 自动回复设置中的客户记忆开关

“回复规则”区域增加一行“客户记忆”设置，位置在历史消息上下文条数设置之后：

- 标签：`客户记忆`
- 控件：`启用客户动态记忆`
- 默认：关闭
- 状态文案：`已开启` / `已关闭`
- 说明：按客户保存加密的对话摘要、偏好和有效人工回复经验，用于后续 AI 回复；关闭后保留已有记忆并停止更新和使用。

设置与现有自动回复设置一起提交，按当前 WhatsApp 技术会话保存。开关关闭时，自动回复仍可使用现有的最近消息上下文，不会因为记忆关闭而停止自动回复。

### 4.3 当前聊天全局翻译

聊天框顶部的主要操作区域增加 `全局翻译` 开关，和人工接管状态放在同一区域。每个聊天引用维护独立的页面状态，默认关闭。

开启后：

- 只处理当前正在打开的客户聊天；
- 翻译当前已经加载的客户、AI 和人工文本消息；
- 下拉加载更早消息时，继续处理当前聊天中新加载的消息；
- 当前聊天收到新消息时，只增量处理新消息；
- 原文始终保留，非中文消息在原文下方显示 `中文：译文`；
- 纯中文消息只显示原文，避免重复显示相同文本；
- 图片说明文字可以翻译，纯媒体消息跳过。

关闭、切换客户、返回最近聊天列表或当前聊天不可见时：

- 取消尚未完成的前端翻译请求；
- 不再发起新翻译请求；
- 隐藏当前页面的译文行，但保留服务端缓存以便下次明确开启时复用。

阿里云机器翻译不可用时，仍显示原文，并提供当前消息级的重试入口；不回退到 AI 翻译服务。

### 4.4 动态呼吸状态

全局翻译和人工接管控件使用统一的状态样式：

- 全局翻译开启：蓝色低幅呼吸；关闭：灰色慢速静息呼吸；
- AI 可回复：绿色呼吸；人工接管中：橙色呼吸；
- 请求处理中保留状态颜色并禁用重复点击；
- 控件同时提供文字、颜色、`aria-pressed` 或等价语义状态；
- `prefers-reduced-motion: reduce` 时停止连续动画，只保留静态颜色和边框变化。

动画只作用于开关和状态胶囊，不让每条消息闪烁，避免干扰阅读。

## 5. 总体架构

### 5.1 记忆链路

消息进入系统后先按原有逻辑归档到 `conversation_messages`，并补充消息来源：`manual`、`auto_ai`、`automation` 或 `unknown`。成功归档后为对应的会话和客户合并一个记忆任务，任务采用“每个客户最多一个待处理任务”的去重策略。

记忆 worker 读取该客户自上次游标之后的新消息，加上最近一段已保存记忆，生成结构化摘要：客户画像/偏好、需求与意图、已确认信息、未解决事项、人工回复风格和置信度。摘要加密保存后更新消息游标、版本、模型指纹和提示版本。任务失败按退避策略重试，超过次数后保留旧记忆并记录脱敏错误状态。

自动回复生成时按以下优先级组合上下文：当前客户最新消息、业务规则和知识库、客户动态记忆、有限的近期原始消息。当前消息和明确业务规则优先于过时记忆；记忆不可用时自动降级到现有近期消息上下文。

### 5.2 翻译链路

聊天页只在当前客户明确开启翻译且当前聊天可见时，提交待翻译消息的 `session`、`chat_ref`、`message_ref` 和原始文本。服务端验证消息归属和长度后：

1. 对纯中文文本直接返回 `SKIPPED`。
2. 对混合语言或非中文文本按原文指纹查缓存。
3. 未命中时调用阿里云 `TranslateGeneral`，源语言使用 `auto`，目标语言使用 `zh`。
4. 加密保存译文缓存并返回当前请求的结果。

翻译缓存只服务于显示，不参与自动回复记忆，不改变 WAHA 消息。

### 5.3 列表滚动链路

`renderChats` 在重建 DOM 前记录：

- 当前列表 `scrollTop`；
- 第一个进入可视区域的 `chat_ref`；
- 该客户相对于列表滚动容器顶部的偏移。

DOM 更新后优先用同一 `chat_ref` 恢复相对偏移；锚点消失时恢复原始 `scrollTop` 的合理范围。搜索和筛选操作显式传递“允许重置位置”的原因，避免和后台刷新混淆。

## 6. 数据模型与隐私

### 6.1 `conversation_messages` 扩展

在现有消息归档表增加 `origin` 字段，默认 `unknown`，用于区分人工回复、AI 回复和自动化回复。历史记录保留 `unknown`，仍可以参与记忆，但置信度低于明确来源的消息。

### 6.2 `customer_memories`

新增客户级记忆表，建议字段：

- `session_name`
- `chat_key_hmac`
- `memory_ciphertext`
- `message_cursor`
- `message_fingerprint`
- `model_fingerprint`
- `prompt_version`
- `version`
- `status`
- `last_error_code`
- `generated_at`
- `updated_at`

唯一键为 `session_name + chat_key_hmac`。客户标识使用已有 HMAC 规则，摘要正文使用现有加密存储能力。接口只返回已脱敏的结构化记忆内容和状态，不返回密钥或原始内部错误。

### 6.3 `conversation_memory_jobs`

新增按客户合并的任务表，建议字段：

- `session_name`
- `chat_key_hmac`
- `state`：`PENDING`、`RUNNING`、`FAILED`、`DONE`
- `attempts`
- `next_run_at`
- `claimed_at`
- `last_error_code`
- `created_at`
- `updated_at`

同一客户的新增消息只推进一个待处理任务，避免实时事件和轮询重复触发摘要。

### 6.4 `machine_message_translations`

新增机器翻译缓存表，建议字段：

- `session_name`
- `chat_ref_hmac`
- `message_ref`
- `source_fingerprint`
- `source_language`
- `target_language`
- `translation_ciphertext`
- `detected_language`
- `status`
- `last_error_code`
- `created_at`
- `updated_at`

唯一键为会话、聊天、消息、原文指纹和目标语言的组合。客户原文和译文均视为客户数据，译文按现有加密能力保存。清理缓存只删除译文缓存，不删除聊天归档或记忆。

## 7. 接口设计

### 7.1 自动回复设置

现有设置读取和保存接口扩展一个布尔字段：

- `GET /api/settings?session=...` 返回 `customer_memory_enabled`。
- `POST /api/settings?session=...` 接收 `customer_memory_enabled`。

已有自动回复开关的权限、会话选择和 CSRF/鉴权流程保持不变。

### 7.2 客户记忆

新增当前客户记忆接口：

- `GET /api/chat/sessions/{session}/memory?chat_ref=...`：读取记忆状态、版本、更新时间和脱敏摘要。
- `POST /api/chat/sessions/{session}/memory/rebuild`：管理员明确要求时重建当前客户记忆。
- `DELETE /api/chat/sessions/{session}/memory?chat_ref=...`：清除当前客户记忆正文和待处理任务，不删除聊天原始记录。

自动回复流程内部通过服务接口读取记忆，不从 HTTP 请求中直接拼接未经校验的上下文。

### 7.3 阿里云翻译设置与当前聊天翻译

沿用现有翻译设置入口但拆分配置语义，增加独立的阿里云配置区域：

- `GET /api/translation/aliyun/settings`
- `PUT /api/translation/aliyun/settings`
- `POST /api/translation/aliyun/test`
- `POST /api/chat/sessions/{session}/machine-translations`

批量翻译请求只接受当前聊天的消息引用和原始文本，服务端限制单次条数、单条字符数和总字符数。返回每个消息的 `READY`、`SKIPPED` 或 `FAILED` 状态以及译文；不返回 AccessKey Secret，不在日志中记录原文和密钥。

现有 AI 销售建议和人工草稿辅助接口继续独立运行。消息气泡上的旧 AI “翻译为中文”按钮移除或改为仅提示启用当前聊天全局翻译，不能再调用 AI 翻译接口。

## 8. 错误处理与边界

- 阿里云未配置：顶部配置状态显示未配置，打开全局翻译时提示先完成配置，不发起请求。
- AccessKey 无效、权限不足或接口失败：原文照常显示，消息级显示可重试状态；不影响聊天加载和发送。
- 单条文本超过接口限制：该条标记失败并说明文本过长，其余消息继续处理。
- 达到 QPS/并发限制：服务端按短退避重试；前端显示翻译中，不阻塞消息阅读。
- 页面切换或开关关闭：前端 AbortController 取消请求，返回结果必须校验当前 `chat_ref` 和请求代次，过期结果不得写入其他客户。
- 记忆摘要失败：保留上一版记忆，自动回复回退近期原始上下文；错误只记录脱敏代码。
- 旧消息没有 `origin`：按 `unknown` 纳入摘要，旧数据不需要强制回填。
- 记忆关闭：不创建新的记忆任务，不将记忆注入 AI 回复；原始归档继续按现有流程工作。

## 9. 安全、迁移与回滚

迁移采用新增表和可空字段的兼容方式，先备份面板数据，再执行迁移。旧代码遇到新增表不会受到影响，新增字段有默认值。阿里云凭据优先使用服务端环境配置或加密设置表，AccessKey Secret 只写入加密字段，读取接口只返回配置状态。

回滚分为三层：

1. 功能回滚：关闭自动回复设置中的客户记忆和聊天顶部全局翻译。
2. 代码回滚：回到迁移前版本；新增表和新增字段保留，不删除任何客户消息。
3. 数据回滚：从变更前备份恢复设置和新增缓存表。恢复前先停止写入并核对备份时间。

本阶段不执行远端部署、容器重启、凭据修改或数据迁移。

## 10. 测试与验收

### 10.1 后端测试

- 自动回复设置读写 `customer_memory_enabled`，不同会话互不混淆。
- 记忆任务按客户合并，人工、AI、自动化消息来源正确归档。
- 记忆关闭时不读取、不更新记忆；开启后摘要任务可重试并保留上一版。
- 摘要和译文加密存储，API 和日志不泄露密钥、原文或内部异常。
- 阿里云 SDK 调用使用 mock，验证 `auto -> zh`、缓存命中、纯中文跳过、长度限制和限流。
- 未打开聊天不会触发机器翻译服务；过期请求结果不会写入当前客户。

### 10.2 前端测试

- 最近聊天列表在异步重渲染后保持锚点和相对偏移。
- 搜索和筛选仍按预期重置列表位置。
- 自动回复设置正确显示和保存记忆开关。
- 全局翻译开关按客户独立，切换客户不继承状态。
- 开启翻译后同时处理入站、AI 出站和人工出站消息；关闭后取消未完成请求。
- 非中文显示原文和中文译文，纯中文不重复显示，翻译失败保留原文。
- 人工接管和翻译状态的呼吸动画存在，并在减少动态模式下停止连续动画。
- 前端 JavaScript 语法检查继续通过。

### 10.3 回归验收

使用当前项目的 Python 运行时执行现有聊天相关测试，并运行前端语法检查。由于当前环境 Docker Desktop Linux 引擎不可用，容器健康、实际 WAHA 响应和线上页面访问需要在引擎恢复后单独验证；在此之前不能宣称已部署完成。

## 11. 交付顺序

1. 完成设计文档自检并等待用户审阅。
2. 用户确认设计文档后，编写逐文件实施计划。
3. 用户确认实施计划和执行方式后，先补测试，再实现设置、记忆、翻译、滚动锚点和动画。
4. 完成本地验证、迁移演练和回滚检查。
5. 用户另行授权后，才进行远端部署或服务重启。
