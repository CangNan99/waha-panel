# WhatsAPP AI管理面板：聊天管理与移动端体验升级设计

**日期：** 2026-09-20  
**状态：** 已获用户需求确认，等待书面设计审核  
**目标版本：** 实施阶段确定的下一个面板版本（本设计阶段不修改版本元数据）

## 1. 目标与成功标准

本设计覆盖管理面板的九项升级：客户备注展示、客户标签展示、客户头像读取、手机端聊天排版、自动回复上下文中的出站消息、上下文数量滑块、自动回复媒体范围、UI 动效审计，以及面板品牌名称统一。

完成后，客户在聊天列表和聊天头部可以直接识别备注、最多四个重点标签和可靠的头像；手机端在 320、375、390、430 CSS 像素宽度下仍能看到并操作“人工接管/恢复 AI 回复”；自动回复可以理解客户与客服双方的最近历史，同时保持自己的出站消息不触发新的自动回复；管理员可以按会话设置历史上下文数量和媒体触发类型；所有页面以 `WhatsAPP AI管理面板` 作为面板品牌。

本设计只改变管理面板的代码、面板 SQLite 中已有的数据流和面板自身页面。不改变 WAHA 镜像、WAHA session 数据结构、WAHA webhook 配置协议、Docker Compose、容器资源、Nginx、端口或外部 AI 服务的接口约定。

## 2. 范围、非目标与不变项

### 2.1 本次范围

- `panel/app.py`：设置读取/保存、Webhook 消息归档与自动回复触发、管理面板品牌和页面路由。
- `panel/chat_service.py`：聊天概览字段、标签摘要、头像适配器、面板侧头像代理、出站消息归档。
- `panel/chat_page.py`：列表/会话头部布局、备注和标签展示、移动端操作区、设置入口和轻量动效。
- 现有 `session_settings`、`conversation_messages`、`message_dedupe` 等面板数据表；优先不新增表、不删除历史数据。
- 与上述行为直接相关的单元测试、前端脚本语法检查和视口验收。

### 2.2 明确不做

- 不修改 WAHA 服务端代码、镜像、版本、会话状态机或其公开 API；面板只调用已有接口。
- 不把 WAHA API Key、头像原始 URL、媒体下载地址或任何 Token 返回给浏览器。
- 不在本版本把原始视频、音频、文件或图片上传给第三方 AI；不新增视觉/语音/文件解析供应商。
- 不改变翻译、销售回复建议、对话总结、跟进任务的既有上下文规则，除非它们复用下文明确的消息归档接口。
- 不引入 Redis、消息队列、前端框架或新的运行容器；保持当前 Python 服务和内联页面结构。
- 不删除或重写已有备注、标签、摘要、会话消息；新字段缺省时必须兼容旧安装。

### 2.3 共享安全原则

- 所有聊天引用继续使用现有的签名/短期引用机制；服务端按会话和聊天引用重新解码，不能信任浏览器传入的原始 `chat_id`。
- 所有读接口继续要求管理员认证；所有写接口继续要求 CSRF 校验。
- 页面只显示“已配置/未配置”等状态，不回显 API Key、密码、Webhook Secret 或加密材料。
- AI 上下文中的客户消息、备注、标签和媒体说明均视为不可信内容，不得改变系统规则或诱导服务端泄露秘密。
- 错误日志使用现有脱敏函数；头像、媒体和 WAHA 响应中的敏感字段不写入普通日志。

## 3. 已确认的产品规则

### 3.1 客户备注展示

1. 备注属于“当前面板会话 + 当前客户”，沿用现有按会话隔离的存储。
2. 在聊天列表和会话头部的主显示行：备注非空时用备注替代手机号/联系人名；没有备注时继续显示联系人名，联系人名为空再退回显示号码。
3. 备注下方保留一个次级信息行：有标签时显示标签；无标签时显示脱敏前端可见的号码/技术标识。
4. 保存、清空备注后，当前列表项和右侧会话头部立即同步，不要求刷新页面。
5. 备注仍使用现有长度上限和文本清理规则；页面使用文本节点渲染，不能把备注解释为 HTML。

### 3.2 客户标签展示

1. 标签摘要位于手机号/技术标识所在的次级行（图 2 标注位置）；同时覆盖左侧聊天列表和右侧会话头部。
2. 默认最多显示四个标签，排序固定为：手动标签在前，AI 标签在后；同一来源内保持数据库顺序。
3. 标签使用紧凑 chip 样式，单个标签单行省略，整行不得把列表项或头部撑出水平滚动；超出四个时显示 `+N`，完整列表仍在现有标签对话框中查看。
4. 没有标签时显示现有号码/技术标识，不留下空白占位行。
5. 手动标签与 AI 标签的读写权限不变：手动标签可编辑/删除，AI 标签只读并由总结流程整体替换。
6. 标签变化后只刷新受影响的列表项和会话头部，不能重置当前消息滚动位置。

### 3.3 客户头像

1. 不再把聊天列表中偶尔存在的多个头像字段当作唯一来源；由面板的 WAHA 适配器使用真实聊天 ID 请求聊天图片接口。
2. 适配器隔离 WAHA 版本差异：优先调用 `GET /api/{session}/chats/{chatId}/picture`，读取响应中的图片 URL/数据；聊天 ID（包括 `@lid`）必须使用服务端解码得到的完整值，不能由手机号拼接。
3. 浏览器使用面板自己的、受管理员认证保护的头像地址；面板负责从 WAHA 读取、校验内容类型和大小后再返回。原始 WAHA URL、API Key 和请求头不出现在 HTML、SSE、日志或 JSON 中。
4. 头像读取采用会话级、聊天级有界缓存和并发上限；正常缓存命中不重复请求 WAHA，失败响应使用短暂负缓存避免刷新风暴。缓存失效时间采用可配置的短期策略，默认不超过 24 小时。
5. WAHA 返回 404、无头像、超时、非法内容或图片解码失败时，回退到联系人名/号码首字母；头像故障不得阻塞聊天列表、消息读取或发送。
6. 列表头像使用懒加载；切换会话时复用缓存。头像代理只允许当前会话的签名 `chat_ref`，并限制响应大小、内容类型和请求超时。

### 3.4 手机端聊天排版

1. 在 `max-width: 820px` 的单列布局中，会话头部改为两层：第一层是返回按钮、头像、备注/联系人名；第二层是始终可见的 AI/人工状态和主要切换按钮。
2. “人工接管”与“恢复 AI 回复”必须在 320 CSS 像素宽度仍可见、可点击，触控目标不小于 44×44 像素；状态文案不能只依赖被隐藏的状态 pill。
3. 备注、标签、当前总结和跟进属于低频操作，移动端收纳到“更多”入口或紧凑操作菜单；桌面端保留现有直接入口。
4. 不允许出现横向滚动；长备注、联系人名、标签和技术标识使用省略或换行策略，不覆盖状态切换。
5. 消息区、输入区和安全区域的高度保持可用；打开更多菜单后仍能关闭并回到当前聊天，不重载消息。

### 3.5 双向消息归档与自动回复触发

1. 对合法的消息事件先做会话、聊天 ID、消息 ID 归一化和 `message_dedupe` 去重，再归档消息；归档和触发是两个独立阶段。
2. 客户入站文字、客户媒体元数据、面板人工出站文字、面板自动出站文字以及 WAHA 回传的 `fromMe` 事件都进入 `conversation_messages`。同一消息有面板发送结果和 Webhook 两条路径时只保留一份。
3. 自己发出的消息只能补充上下文，永远不能触发自动回复、更新客户入站活动或绕过人工接管状态；这条规则优先级高于所有媒体开关和时间段设置。
4. 面板发送成功后立即用返回的消息 ID 归档出站文本；Webhook 随后到达时按消息 ID 幂等跳过。若面板发送响应没有消息 ID，则使用该次已验证的本地发送请求号作为仅面板来源的归档 ID；若 WAHA Webhook 本身没有消息 ID，则不归档、不触发，只记录脱敏诊断，避免无法去重时产生回声回复。
5. 自动回复触发条件保持收紧：仅消息事件、私聊、非状态消息、非 `fromMe`、有有效聊天/消息 ID、消息类型已被设置允许、未人工接管、处于允许时间段且自动回复已开启。
6. 归档失败、消息 ID 无法归一化或历史回填失败时，自动回复采用 fail-closed：记录脱敏错误并不发送新消息，避免在上下文不完整时误答或重复答复。
7. 首次启用或本地历史不足时，允许按当前上下文上限从 WAHA 分页读取最近消息，统一经过同一归档/去重函数；单次回填最多读取 100 条，不做无界历史同步。

### 3.6 上下文数量滑块

1. 自动回复设置新增“每一方的历史消息数”滑块，范围 `5`–`50`，步长 `1`，默认 `5`。
2. 数值 `N` 表示最多读取客户最近 `N` 条和客服/自己最近 `N` 条，合并后按时间升序提供给 AI；因此默认是最多 10 条历史上下文，最大是最多 100 条。
3. 当前触发自动回复的客户消息单独作为当前输入传给 AI，不占用滑块的历史配额；上下文中必须包含此前的自己发出的消息。
4. 仍受现有字符上限约束；当字符达到上限时从最早消息开始裁剪，不破坏当前触发消息。
5. 设置按会话保存在现有 `session_settings` 键值表中。缺失、非法、超范围值统一回退到 `5`，不能因旧安装数据导致服务启动失败。
6. 该滑块只改变自动回复历史读取；翻译、建议、总结和跟进继续使用各自当前的固定历史规则。

### 3.7 自动回复媒体范围

1. 设置页新增四个独立选项：图片、视频、音频、文件；默认全部关闭。
2. `audio` 和 `ptt` 归入音频，`document` 归入文件；无法识别的媒体类型默认不触发。
3. 打开某一类型后，来自私聊客户的该类型消息可以触发自动回复；群聊、状态消息、自己发出的媒体以及人工接管中的消息仍然忽略。
4. 发给 AI 的媒体内容使用受限的文本标记，例如类型、文件名、MIME、大小（若可靠）和 caption/body；不得下载或上传原始二进制，不声称 AI 已经“看见/听见”媒体。
5. 媒体开关关闭时，消息仍可被安全归档为上下文元数据，但不会触发自动回复；已有文字 caption 是否参与触发由媒体类型开关决定，而不是绕过开关。
6. 设置响应只返回布尔值和公开选项，不返回任何文件内容、远程 URL 或凭据。

### 3.8 UI 动效审计结果

本节遵循 `find-animation-opportunities` 的只读审计要求：只保留能够说明用途、频率、速度和功能收益的少量动效；不把动效作为装饰性改造目标。当前页面已有 `0.18s` 控件过渡、`0.2s ease-out` toast 入场和 `prefers-reduced-motion` 处理，建议沿用这些词汇。

#### Part 1 — Opportunities table

| # | 位置 | 当前行为 | 目的 | 频率 | 建议动效 |
| --- | --- | --- | --- | --- | --- |
| 1 | `panel/chat_page.py:57` 附近的对话框，以及 `showModal()/close()` 调用点 | 对话框瞬间出现/消失，空间来源不明显 | Spatial consistency；Preventing a jarring change | 偶尔 | 入场 `opacity: 0; transform: scale(.97)` 到稳定态，`200ms ease-out`；退出使用同一路径；减少动效时只保留温和 `opacity` 过渡，不使用弹跳 |
| 2 | `panel/chat_page.py:31,69` 的 toast | 已有 `200ms ease-out` 入场，4200ms 后直接移除 | Spatial consistency；Preventing a jarring change | 偶尔 | 增加关闭状态：`opacity:1; transform:translateY(0)` 到 `opacity:0; transform:translateY(6px)`，`200ms ease-out`，过渡完成后再移除；减少动效时仅 `opacity 120ms ease-out` |

上述候选均只动画 `transform` 和 `opacity`，不动画尺寸、颜色大面积重排或消息数据本身；实现时必须保留键盘焦点、关闭行为和 `prefers-reduced-motion` 兼容。

#### Part 2 — Rejected candidates

- 消息列表每次 SSE 更新都淡入：拒绝。消息更新可能达到每天数十至上百次，属于用户正在阅读的数据，动效会遮挡时间线并增加认知负担。
- 聊天列表每个 hover/选中项增加位移或弹跳：拒绝。该区域是高频导航，现有 `0.18s` 背景/边框反馈已经足够；额外位移会降低定位稳定性。
- AI/人工状态切换做大幅度缩放或弹跳：拒绝。它是功能状态而非庆祝场景，且移动端空间紧张；使用颜色、文案和轻微状态过渡即可。
- 头像加载做旋转、呼吸或渐变装饰：拒绝。头像是识别信息，加载失败还需要稳定地回退首字母，装饰动效会干扰识别并掩盖错误。
- 骨架屏、空状态和普通列表做大范围 stagger：拒绝。聊天管理是信息密集型工作台，连续进入动效会延迟可读性；保留现有轻量加载提示。

#### Part 3 — Verdict

这个界面不需要“更活泼”，只需要在对话框、toast 和手机端视图切换这三个瞬间补足空间关系；其余高频数据和状态应保持稳定。最高杠杆项是移动端列表/详情切换，因为它同时解决“内容瞬移”和手机端导航迷失。实施时若要把某一行转成独立执行任务，应以该行的精确值为准，不扩大动效范围。

### 3.9 品牌名称

1. 面板浏览器标题、状态控制台顶部品牌、聊天管理页顶部品牌和自动回复设置页标题统一使用精确文本 `WhatsAPP AI管理面板`。
2. “WAHA 服务”“WAHA 状态”“WAHA / 技术会话”等词只在说明底层依赖、连接状态或技术名称时保留，不能作为面板产品名。
3. 其他管理页（包括旧版/业务页）若存在独立页面标题，也使用同一品牌；不改变 API 路径、技术会话名、镜像名或 WAHA 控制台本身。

## 4. 推荐架构

### 4.1 组件职责

| 组件 | 责任 | 不负责的事情 |
| --- | --- | --- |
| `ChatService.overview` | 读取聊天基础资料、备注、四个标签摘要和面板头像地址 | 不把原始 WAHA 凭据交给浏览器，不在页面层拼接真实 chat ID |
| `ChatService` 的头像适配器/缓存 | 以完整 chat ID 调用 WAHA picture 接口、验证响应、缓存和降级 | 不改变 WAHA 头像数据，不下载无界大小的文件 |
| `PanelRequestHandler` 聊天路由 | 鉴权、CSRF、参数校验、调用服务并输出安全 JSON/图片 | 不直接访问 SQLite 或组装 AI prompt |
| `PanelState` 消息归档管线 | 事件归一化、去重、双方消息归档、触发门控、上下文读取和自动回复 | 不让 `fromMe` 事件触发 AI |
| `session_settings` | 保存每会话的上下文数量和媒体选项 | 不保存 API Key 明文到页面响应 |
| `chat_page.py` | 渲染备注/标签/头像、移动布局、设置控件和有限动效 | 不在浏览器端决定安全边界或调用 WAHA |

### 4.2 聊天概览数据流

1. 浏览器请求现有 overview 接口，服务端先验证管理员会话和 WAHA 技术会话。
2. `ChatService` 读取 WAHA 聊天页，按页批量读取面板备注和标签摘要；每一项返回 `chat_ref`、联系人名、显示标识、备注、四个标签、溢出数量、面板头像地址和当前接管状态。
3. 若某项头像未命中缓存，前端通过面板头像地址懒加载；头像失败只替换该项的首字母，不让 overview 失败。
4. 保存备注/标签后发布现有 refresh 事件或局部更新事件；前端只更新对应项目和当前头部。

建议的公开概览字段（均不含密钥）如下：

```json
{
  "chat_ref": "<signed-reference>",
  "name": "联系人显示名",
  "display_id": "号码或技术标识",
  "note": "客户备注或空字符串",
  "labels": [
    {"label": "手动标签", "source": "manual"},
    {"label": "AI 标签", "source": "ai"}
  ],
  "label_overflow": 0,
  "avatar_url": "/api/chat/sessions/<session>/avatar?chat_ref=<signed-reference>"
}
```

示例中的引用、名称和标签只表示字段契约，不代表真实客户数据；实现和测试不得写入真实号码、消息、Token 或密码。

### 4.3 头像适配器与代理

- 在 WAHA client 与 `ChatService` 之间增加单一 `get_chat_picture(session, chat_id)` 适配方法，以便不同 WAHA 版本的响应结构只在一个位置处理。
- 适配器只接受服务端解码出的 `chat_id`，设置明确连接/读取超时；响应先检查状态、Content-Type、Content-Length/实际大小，再转换为面板可返回的图片。
- 缓存键为 `(session_name, chat_id)`，容量有界，读取并发受限；命中时不重复请求，连续失败使用短暂负缓存。
- 头像代理路由重新验证 `chat_ref` 与 session 一致性，并返回 `Cache-Control: private`、`X-Content-Type-Options: nosniff` 等安全头；不允许开放代理任意 URL。
- 图片无法使用时由前端稳定显示首字母；前端 `img.onerror` 只能切换占位，不自动循环重试。

### 4.4 消息归档与触发门控

Webhook 和面板发送共用以下顺序：

```text
解析事件/发送结果
  → 归一化 session、chat_id、message_id、方向、类型、文字/媒体说明
  → message_dedupe 幂等检查
  → conversation_messages 归档（文本或安全媒体标记）
  → 若为 fromMe/群聊/状态/未启用媒体/人工接管/未到时间/未启用，则停止
  → 计算 N 对 N 历史上下文
  → 调用 AI 并发送
  → 用返回消息 ID 归档自动出站消息
```

归档函数必须是幂等的；自动发送前若无法完成当前入站归档或上下文读取，则不发送。自动发送后的归档失败要记录错误并保留发送结果，不进行未知状态下的自动重试。

### 4.5 上下文构造

- 从 `conversation_messages` 分别取最近 N 条 `inbound` 和 N 条 `outbound`，以数据库记录时间/ID 合并排序。
- 当前触发消息通过 `incoming_text` 单独传入，查询时排除同一消息 ID；这样不会因消息重复存储而在 prompt 中出现两次。
- 媒体记录使用明确的 `[客户发送图片]`、`[客服发送文件]` 等标记，并附带经长度限制的 caption/文件名；不把远程 URL 当作可执行指令。
- 保持字符上限、知识库和业务上下文的现有顺序；上下文数量设置只影响历史消息段。
- 本地记录不足时按 `min(2*N, 100)` 回填 WAHA 最近消息；回填结果再经过 message ID 去重，失败则 fail-closed。

### 4.6 设置契约

建议使用以下键值（名称在实施阶段可保持一致，不另建表）：

| 键 | 类型/范围 | 默认值 | 页面含义 |
| --- | --- | --- | --- |
| `auto_reply_context_per_side` | 整数 `5..50` | `5` | 客户和客服各取多少条历史消息 |
| `auto_reply_media_types` | JSON 对象，键为 `image/video/audio/file`，值为布尔 | 全部 `false` | 哪些客户媒体可以触发自动回复 |

读取设置时做严格解析和回退；保存时只接受白名单键和范围，忽略或拒绝未知媒体类型。API 响应返回 `auto_reply_context_per_side` 和 `auto_reply_media_types`，不返回任何敏感设置值。

### 4.7 移动端 DOM/CSS 结构

会话头部采用语义分区：`conversation-head` → `conversation-title`（返回、头像、主/次文本）+ `conversation-primary-actions`（状态、人工/恢复）+ `conversation-more`（备注、标签、总结、跟进）。桌面端可以把三组排列在同一行，移动端用两行 grid/flex；所有中间容器设置 `min-width: 0`，标签行设置溢出策略。

“更多”菜单必须使用现有 dialog/按钮可访问模式，支持键盘 Escape、点击外部关闭和焦点回收；不能只通过 hover 才能打开。

## 5. 数据兼容、迁移与回滚

1. 首选只增加 `DEFAULT_SETTINGS` 和 `session_settings` 键，不新增迁移文件；旧安装启动时通过现有默认值补齐缺失设置。
2. `conversation_messages` 已有 `direction`、`message_id`、`content`、`created_at` 字段，媒体标记和出站 ID 优先复用，不修改历史行。
3. 若实现发现必须新增索引或可选列，只能使用幂等的 additive migration，并在提交前提供升级前后备份和回滚说明；本设计不授权删除/重建表。
4. 回滚代码后，新增设置键可以保留而被旧版本忽略；旧的 20 条上下文逻辑必须仍可通过代码回退恢复，不得让旧版本因未知键启动失败。
5. 头像缓存是可丢弃数据，回滚时清空缓存不会影响聊天、标签、备注或消息历史。
6. 任何数据库写入、配置发布或服务重启都必须在实施阶段单独列出目标、备份、回滚和验证结果；本设计阶段不执行这些操作。

## 6. 错误处理与安全验收

### 6.1 错误处理

- 头像：超时/404/非法图片 → 记录脱敏诊断、返回占位首字母，overview 仍成功。
- 标签/备注摘要：单项读取失败 → 保留号码/技术标识和空标签，不让整页失败；写入失败明确提示且不伪造成功状态。
- 设置：非法滑块或媒体值 → 返回可读校验错误，保留旧值；旧值损坏时安全回退到默认值。
- Webhook：无效签名、无会话、无聊天 ID/消息 ID、归档错误 → 拒绝或忽略，不调用 AI；错误日志不得包含原始密钥和完整媒体 URL。
- AI/WAHA 发送：沿用现有未知发送状态语义；不因“可能已发送”而自动重试，消息记录和日志标记可核查状态。

### 6.2 安全验收

- 通过浏览器开发者工具确认不会看到 WAHA API Key、Webhook Secret、原始头像 URL、媒体下载 URL 或 `.env` 值。
- 头像代理无法被改写为任意 URL；错误 `chat_ref`、跨会话 `chat_ref`、过期引用均返回拒绝。
- 自己发出的文字、图片、视频、音频和文件事件均不能产生新的自动回复；重复 Webhook 不能增加历史行或重复发送。
- 媒体元数据经过长度限制和控制字符清理；文件名不能形成 HTML、URL 或系统指令。
- 手机端更多菜单和状态切换保留键盘焦点、ARIA 标签和最小触控尺寸。
